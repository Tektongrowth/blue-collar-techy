# Blue Collar Techy site: notes for anyone working in this repo

Technical notes about this site, checked against main on 2026-10-13. There is no brain for this site; positioning notes are below. Rules for every Tekton site are in Mason's website policy.

## Deploy and hosting
- `.github/workflows/deploy.yml` runs on pushes to `main` and to `draft/**` branches, and on manual runs.
- There is no build step. The workflow copies the site's files into `site/` and uploads that folder (`pages deploy site`) to the Cloudflare Pages project `blue-collar-techy`. Markdown, Python, dotfiles, `content-ops/`, `youtube-scripts/` and `functions/` are left out; `functions/` deploys as Pages Functions from the repo root.
- `main` deploys production. Any other branch deploys a preview on a Pages branch named after it with `/` turned into `-` (`draft/<slug>` becomes `draft-<slug>`).
- Approving a `draft/*` pull request turns on squash auto-merge (`.github/workflows/auto-merge.yml`). The Telegram approve button calls `functions/api/telegram-webhook.js`, which squash-merges the pull request. Either way the merge to `main` deploys production.
- Host handling is in `functions/_middleware.js`: `www.bluecollartechy.com` and `blue-collar-techy.pages.dev` get a 301 to `https://bluecollartechy.com`, and every other `*.pages.dev` host gets `X-Robots-Tag: noindex, nofollow, noarchive` plus a `Disallow: /` robots.txt.
- Cloudflare serves `about.html`, `work-with-me.html` and the blog posts without `.html`; the `.html` address answers with a 308 to the clean one. Canonicals use the clean URL.
- `.github/workflows/post-merge.yml` runs when `blog/*.html` changes on `main`. It marks the post published in `content-ops/content-calendar.json` and rebuilds `sitemap.xml`.
- `.github/workflows/seo-monitor.yml` runs weekly and commits `.seo-state.json`.

## Where things live
- Pages are hand-written static HTML, each with its own `<style>` block and head tags (most also carry their own JSON-LD): `index.html`, `about.html`, `work-with-me.html`, `blog/*.html` (listed in `blog/index.html`), `resources/`, and the tools `market-scan/`, `gbp-check/`, `qr-generator/`, `utm/` and `built-to-last/`. There is no shared CSS file.
- Server code is Pages Functions in `functions/api/`: `/api/scan` (market scan), `/api/gbp-check`, `/api/find-review-url` (QR generator), `/api/contact` (the work-with-me Growth Systems Call form: upserts the GHL contact, tags it `bct-work-with-me`, adds the request as a note, and answers 502 if GHL refuses), `/api/subscribe` (email sign-ups) and `/api/telegram-webhook`.
- `/api/contact`, `/api/gbp-check`, `/api/scan` and `/api/subscribe` each email an internal new-lead alert through Resend (`notifyLead`, copied into each file): to `LEAD_NOTIFY_EMAIL`, else `SCAN_NOTIFY_EMAIL`, else nick@tektongrowth.com, from `LEAD_NOTIFY_FROM`, else `leads@tektongrowth.com`. It sends from tektongrowth.com because bluecollartechy.com has no Resend DKIM. No alert goes out without `RESEND_API_KEY`. The alerts and GHL pushes run in `context.waitUntil`, so they finish after the response. Change all four copies together.
- GA4 and the lead attribution helpers (`bctGetAttribution`, `bctTrackLead`) are in `js/tracking.js`, which most pages load. It stores first-touch referrer, landing URL, UTMs and gclid/fbclid in localStorage for 90 days; every form sends it as `attribution`.
- `functions/_lib/attribution.js` turns that into one `src-*` tag (src-google-organic, src-direct, src-ai-referral, src-paid, and so on), a GHL `attributionSource`, a contact note and rows in the lead alert email. All four lead functions upsert the GHL contact through it.
- Images are in `images/` and `logos/`. The primary logo is `logos/bct-logo-horizontal.svg` (mark: `logos/bct-logo-mark.svg`); colors, fonts, usage rules and the merch files are in `brand/` (see `brand/README.md`). The other SVGs in `logos/` are an older April design, not the primary logo. The sitewide social image is `og-image.jpg` at the root. `photos/` is gitignored and never deploys.
- `sitemap.xml` is generated by `post-merge.yml` from each page's canonical URL, skipping pages with a noindex robots meta and the files in its `SKIP` list. Don't hand-edit it.
- `robots.txt` and `llms.txt` are hand-written.
- `content-ops/` holds the blog pipeline: the content calendar, keyword data, `voice.md` and the draft scripts.

## Positioning and copy
- Read `content-ops/voice.md` before writing copy. It holds the copy rules (no em dashes, banned hype words, no fake urgency, no overclaims) and the blog post structure.
- Two lanes: Blue Collar Techy teaches, Tekton Growth builds and manages. The homepage tag says "Learn it here · build it with Tekton" (`index.html:865`) and the work-with-me page says "Learn it here. Build it with Tekton." (`work-with-me.html:572`).
- The audience is contractors doing about $1M to $3M a year (`index.html:825`, `work-with-me.html:598`).
- The homepage offer is five cards in this order: AI for contractors, contractor marketing, online trust, systems that keep up, and a done-for-you buildout by Tekton Growth (`index.html:864-891`).
- The "Start learning the pieces" topics are AI for Contractors, Contractor Marketing, and Website · Google · Reviews (`index.html:901-931`).
- Copy leads with the contractor's business-side pain in plain words: missed calls, leads that sit too long, estimates nobody follows up on (`index.html:852-854`).
- `work-with-me.html` has one commercial action, the Growth Systems Call. Its intake asks for revenue range, trade, what feels broken, the main bottleneck, and the website or Google listing (`work-with-me.html:655-739`).
- Nick's field background, a hardscape contractor turned tech operator, is the proof point (`about.html:652`, the founder card at `index.html:839`).
- Older pages still break the voice rules: 15 HTML files contain em dashes, including the `<title>` of `about.html`.

## Traps
- `_headers` noindexes only `/utm/*`, `/under-construction*` and the brand-kit files under `/brand/*` (the sitewide noindex was removed on 2026-10-13). Don't add a `/*` rule back: it hides the whole site from search.
- There is no `404.html`, so unknown paths return 200 with the homepage.
- Until 2026-10-13 the deploy uploaded the whole repo, so notes and scripts were public pages. Now anything that isn't Markdown or Python, outside the left-out folders, still goes live: keep notes in Markdown or under `content-ops/`. The repo itself is public, so never commit anything private either way.
- Responses carry `cache-control: public, s-maxage=604800`, set in the domain's Cloudflare account, not in this repo. A removed file can still be served from Cloudflare's cache until that cache is purged.
- `post-merge.yml` commits the refreshed sitemap with `[skip ci]`, so the new sitemap only goes live with the next deploy.
- `llms.txt` mixes `.html` links, which redirect, with clean URLs.
- Tests for the lead functions and attribution helpers are in `.tests/` (a dot folder, so it never deploys). Run them with `node --test .tests/` (Node 20+); there is no build step.
